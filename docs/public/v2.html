One Spec, Complete

No split files. No hidden conventions. Server data, state, mutations, and view in one verifiable object:

export default {
  route: '/dashboard',
  meta: { title: 'Dashboard', styles: ['/app.css'] },
  server: {
    data: async (ctx) => ({
      user: await db.users.find(ctx.cookies.userId),
      stats: await db.stats.forUser(ctx.cookies.userId)
    })
  },
  state: { filter: 'all' },
  mutations: {
    setFilter: (state, event) => ({ filter: event.target.value })
  },
  view: (state, server) => `
    <main id="main-content">
      <h1>Hello, ${server.user.name}</h1>
      <select data-event="change:setFilter">
        <option>All</option>
        <option>This week</option>
      </select>
      <p>${server.stats[state.filter].total} requests</p>
    </main>
  `
}

What Pulse Forbids

Constraints aren't limitations — they're guarantees. Pulse stops you from shipping broken code:

One Spec Per Page

Every page is exactly one plain JS object. You can't accidentally split it across files or decouple data from view.

Pure Mutations

State changes must be synchronous, side-effect-free functions. State is predictable, testable, instantly debuggable.

Dialogs Always Render

Modals must be in the DOM unconditionally. Opened with data-dialog-open, never conditionally rendered based on state. Avoids a common agent mistake.

Constraints Always Enforced

min/max bounds on state are guaranteed after every mutation. State literally cannot violate them.

CSRF Protection Mandatory

Form submissions are protected by default. No opt-out. You can't forget it.
